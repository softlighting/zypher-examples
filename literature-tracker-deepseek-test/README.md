这是一个使用 DeepSeek API 测试文献追踪助手核心功能的测试项目。

## 测试目的

验证文献追踪助手的提示词和交互逻辑在 DeepSeek 模型上的表现，包括：

1. **基本对话能力** - 测试模型的基础响应质量
2. **文献搜索场景** - 测试模型理解学术文献搜索需求的能力
3. **多轮对话能力** - 测试模型保持上下文的能力
4. **复杂任务理解** - 测试模型处理复杂研究需求的能力

## 测试场景

### 测试 1: 基本对话能力

测试模型作为文献追踪助手的基本自我介绍能力。

**用户输入**:
```
你好！请介绍一下你的功能。
```

**评估指标**:
- 回复是否准确描述了文献追踪助手的功能
- 语言是否专业和友好
- 回复是否结构清晰

### 测试 2: 文献搜索场景

测试模型理解和响应文献搜索请求的能力。

**用户输入**:
```
我想搜索最新的关于 transformer 架构的论文，你能帮我吗？
```

**评估指标**:
- 是否理解了搜索需求
- 是否提到需要使用的工具（search_papers）
- 是否给出了合理的搜索建议

### 测试 3: 多轮对话能力

测试模型在多轮对话中保持上下文的能力。

**对话流程**:
1. 用户: "我想追踪深度学习方向的论文。"
2. 用户: "特别是关于 transformer 和注意力机制的论文。"
3. 用户: "你能总结一下我们刚才讨论的内容吗？"

**评估指标**:
- 是否能理解上下文关系
- 回复是否连贯
- 总结是否准确

### 测试 4: 复杂任务理解

测试模型理解和规划复杂研究任务的能力。

**用户输入**:
```
我正在做一个关于大语言模型在医疗领域应用的研究项目。
我需要：
1. 找到最新的相关论文（最近3个月）
2. 特别关注模型的准确性和可解释性
3. 建立一个追踪列表
你能帮我制定一个文献检索和管理计划吗？
```

**评估指标**:
- 是否理解了多个需求点
- 是否提供了系统的计划
- 建议是否实用和专业

## 性能指标

测试会记录以下性能指标：
- **Token 使用量**: 每个测试的输入/输出 token 数
- **响应质量**: 人工评估模型回复的相关性和准确性
- **上下文理解**: 多轮对话中的上下文保持能力

## 与原项目的关系

本测试项目独立于原 `literature-tracker` 项目，主要目的是：

1. 验证 DeepSeek 模型的性能
2. 为未来可能的 DeepSeek 集成提供参考
3. 比较不同模型（Claude vs DeepSeek）在相同任务上的表现

原项目使用 Zypher 框架和 Anthropic Claude 模型，本测试项目直接调用 DeepSeek API。

## 扩展建议

如果测试结果良好，可以考虑：

1. 创建 DeepSeek 的自定义模型提供者集成到 Zypher
2. 实现模型切换功能，允许用户选择使用的 AI 模型
3. 进行更详细的性能对比测试
4. 评估成本效益（DeepSeek vs Claude）
